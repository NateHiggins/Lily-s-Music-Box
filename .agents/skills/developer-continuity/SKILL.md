# Continue the actual project

Recover enough verified context to act, then continue the authorized task. Do not
restart the project, replay the chat or turn intake into an approval ceremony.
Keep changing checkpoint facts in the existing handoff/ledger, not in this skill.

## Arrive with evidence

1. Read [DOCS.md](../../../DOCS.md), [AGENTS.md](../../../AGENTS.md), the applicable
   Bible rulings, then the newest checkpoint in [HANDOFF.md](../../../HANDOFF.md)
   and relevant open clauses in [TASKS.md](../../../TASKS.md). The handoff is an
   index, not a replacement for canon or proof. Historical sections may be stale.
2. Resolve the latest human objective and accepted scope changes. An earlier
   brainwave, INERT proposal or another agent's claim does not silently override
   later decisions. Match repeated task IDs by section/context. Keep unfinished
   clauses when archiving completed queue text; retain source/evidence pointers.
3. Inspect the real checkout before editing: cwd, Git root/branch/HEAD, staged,
   unstaged and untracked paths, upstream and worktrees. Normal development is
   C:/PleaseRemainOnTheLine; an app-attached v2-baseline checkout can be older.
   Use explicit workdirs. Fetch and compare before merging; preserve newer work.
4. Trace implemented behavior through actual loaders, scenes and state owners.
   External C:/ov prototypes/research are deliveries or proposals until consumed
   and tested. Verify manifest hashes/revisions and current consumers; a native
   clearance report is not Godot integration or artistic acceptance.

Use the relevant existing [Godot](../godot-development/SKILL.md),
[Blender](../blender-asset-development/SKILL.md),
[texture/shader](../godot-textures-and-shaders/SKILL.md) or
[pixel-art](../godot-pixel-art/SKILL.md) workflow. Do not copy those guides into
another handbook or load every project report by default.

## Keep the hard-won boundaries

- Main is the integration line. Stage named paths; preserve other contributors'
  dirty files, branches and shared stash. Never fake a clean verification tree
  by hiding work. Follow the repository's supported isolation/verifier workflow
  when preserved unrelated work prevents an in-place check. Temporary checkouts
  use short Windows paths and are cleaned up only after their work is safe.
- Inspect LF-normalized import diffs and UID conflicts against origin/main.
  Restore only demonstrated generated churn. Write UTF-8 explicitly; hash-bound
  text uses explicit LF and the repository's -text attributes. Do not bulk stage
  generated UIDs, copied review packets or reference textures.
- Godot and GPU work share the first-come lane. Inspect lane status and run only
  through repository wrappers; never kill another owner's process. Verify the
  hash-pinned patched Vulkan engine, not just project.godot's feature version.
  Official-engine fallback is not evidence of clean reflection-atlas teardown.
- Preserve inventory, work orders, residents, reading/publication, clock/weather,
  dialogue/input and validated save owners. The companion presents those facts;
  it cannot manufacture them. Temporal render clocks and cinematic cutaways must
  not become gameplay-clock writers. Keep the explicit V1 rollback.
- Separate implemented, native-verified, loaded diagnostic, runtime-qualified,
  actually played and artistically accepted. Only test-written schema2 contracts
  establish runtime proof. A wrapper exit0, parsed file, screenshot, authored
  test or manually closed window does not establish a completed pass.
- Reuse evidence only for unchanged consumed inputs and claims. Freeze inputs
  during source-bound runs; inspect each stage's receipt and stderr. Preserve
  original failures. A genuine parse error is not cured by calling it stale
  cache. Never repin an old receipt or weaken a gate to expedite a merge.
- Minimize launches and travel. Use nearby test fixtures with real affected input;
  combine related checks in one composed world when supported. A physical-only
  survey still includes every physical draw but does not repeat or accept the
  skipped interaction programmes. Do not rerun unchanged hose/long walks for
  report edits. Movie recording is not a gameplay frame-time benchmark.

## Leave a small, usable handoff

Update the current checkpoint at the top of HANDOFF.md and reconcile TASKS.md.
Put detailed receipts in their existing subsystem ledger/archive. Record:

- exact local/upstream/merge hashes and whether work is committed, pushed and
  merged (three different states); preserved dirty/untracked work and custody;
- the active objective, actual implementation and smallest remaining gap;
- what ran, settings/engine/fixture scope, test-written contracts and original
  failures; what was not played or accepted and which signatures are stale;
- external deliveries not yet integrated, other-agent ownership and any genuine
  user decisions; the next concrete action with a reproducible entry point.

Do not make another giant history file. Keep one evidence archive per coherent
checkpoint, retaining raw failed receipts and provenance without shipping every
intermediate render. Link the current source rather than duplicating it. Update
skills only when a demonstrated lesson changes future execution.

Before saying a handoff is ready, re-read its links against current Git/runtime
state, validate changed skills/documents, and reconcile intervening work. Report
any real blocker plainly. Continue authorized independent work; ask only for a
missing decision that materially changes the outcome. Archiving or taking a
break does not mark the broader V2 goal complete or authorize new development.
