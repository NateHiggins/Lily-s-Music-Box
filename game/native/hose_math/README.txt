Candidate hose numerical kernel

This Windows x86-64 GDExtension owns numerical buffers only. The existing
GDScript owners retain world queries, native skin, elapsed time, energy,
grabbing, mechanical facts, inventory and persistence. It is not installed
in the building's eight hose cabinets. Release/contact remains unfinished.

The adapter validates the DLL against build_manifest.json and, in a source
checkout, validates the C++ source binding before loading the extension.
Missing binaries/non-Windows platforms use the retained GDScript solver;
an invalid present binary fails closed. No non-Windows build is qualified.

Build dependencies: Python, CMake, Ninja, Zig, and a clean godot-cpp checkout
at 27d9dd23c83871e0619fca5dc2cddfbfd69e926a. The build tool downloads nothing.
Use separate short local build paths. From the repository root:

python tools/build_hose_math.py --sdk-source <godot-cpp> --sdk-build <sdk-build> --build-dir <module-build> --zig <zig.exe>
python tools/build_hose_math.py --verify

Commit the source, descriptor, profile, manifest and DLL together. Keep the
PDB and SDK/build caches outside the checkpoint. Rebuild after changing any
source bound by the manifest. Preserve the third-party notices in licenses/.
The Godot lane wrappers remain mandatory for every runtime verification.
